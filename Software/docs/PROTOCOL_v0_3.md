# Automaton Protocol v0.3 Draft

This document describes the current development protocol. It is versioned and deliberately not treated as a permanently frozen wire format yet.

## RCB CAN transport

- Classic CAN, standard 11-bit identifiers.
- Fixed 8-byte application payloads.
- Eight independent point-to-point CAN buses; one RCB per physical CCB channel.
- `PROTOCOL_VERSION = 1` in messages that carry an explicit version byte.
- Host session ID is 32-bit and regenerated by a new host process/runtime.
- Reconnection/reset invalidates arming; a new valid session and explicit ARM are required.

## Motion command

Current single-servo command:

```text
byte 0      protocol version
bytes 1..4  host session ID, little-endian
byte 5      RCB servo channel 0..31
bytes 6..7  signed normalized target -1000..+1000, little-endian
```

This is intentionally an actuator goal, not a raw PCA9685 register write.

All channel profiles are disabled by default, and physical output is compile-locked in v0.3.

## ARM behavior

ARM is a state transition, not merely a boolean packet:

```text
ARM_REQUEST
  -> validate logic power / CAN freshness / session / GLOBAL allow
     / PCA presence / role config / fault state
  -> assert LOCAL_SERVO_ENABLE (only in a future unlocked build)
  -> ARMING_WAIT_POWER_GOOD
  -> wait for required bank PG within bounded timeout
  -> ARMED
```

`ARM_PENDING` means the request passed preconditions and is waiting for bank power-good. `STATUS_ARMED` is the authoritative indication that the transition completed.

Any failure during this sequence drops local enable and leaves the node disarmed.

## CCB Supervisor transport

The Pi/Supervisor link is a separate fixed-size binary UART protocol with CRC, plus an independent GPIO heartbeat.

The UART protocol covers:

- HELLO/status;
- session begin;
- keepalive;
- ARM/DISARM request;
- CAN-channel enables;
- remote-channel power requests;
- service state;
- fault clear/status primitives.

The Supervisor—not the Pi protocol parser—retains final authority over the global servo permission output.

See:

```text
Central Control Module/src/protocol/supervisor_protocol.*
Raspberry PI 5/automaton/ccb_protocol.py
```

## Items intentionally still evolvable

- future grouped/multi-servo motion frames;
- motion trajectory timestamps;
- local interpolation policy;
- richer telemetry scheduling;
- firmware update transport;
- diagnostic/event history;
- fault-latching categories;
- protocol compatibility negotiation beyond the current version field.

Wire-format changes should bump the relevant protocol version rather than being silently introduced.
